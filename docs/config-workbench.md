# 配置工作台 · 第一阶段

侧栏新增“配置工作台”。读取当前 Preset 与脱敏配置哈希，按后端字段元数据生成四组表单：检索与规划、融合与重排、生成与评估、数据与索引。

- 支持布尔/枚举选择、数值、字符串、可空值和 JSON 对象编辑。参数名称与环境变量名便于开发者定位；新增注册模式自动出现在组件选项中。
- 输入时比较当前值与草稿；点击“校验草稿”检查类型、范围、跨字段约束、组件及指标名称、权重。错误展示字段定位。
- 索引相关参数标记兼容性检查提醒；这是保守提示，是否实际需要重建仍由 IndexManifest 判断。
- 第一阶段草稿仅保存在当前页面内存中；校验不保存、不应用配置。刷新后草稿丢失，“重新读取生效配置”丢弃当前草稿。
- “恢复默认设置”一键替换全部草稿字段为后端 Settings 内置默认值（不读取 .env、环境变量或当前 Preset），并清空草稿密钥引用。它与“重新读取生效配置”不同：前者恢复项目初始默认值，后者恢复当前服务实际配置。默认恢复后仍可查看差异并校验，当前运行配置和真实密钥不受影响。
- 密钥与 service_preset 不进入编辑表单。现有 Preset 环境变量引用保留在草稿请求中，校验不读取或解析密钥。
- GET /v1/config/schema 提供字段描述；POST /v1/config/draft/validate 返回 valid/errors/activation。草稿校验不读取 .env 或系统环境变量，不加载 Provider 或调用模型。
- 旧 Preset 校验 API 保留；新草稿接口返回结构化字段错误供 UI 使用。非法分组模式和未知指标会拒绝。
- 当前校验只确认配置结构和已实现的约束，不验证凭据、端点连通性或本地模型可用性。

第二阶段计划增加 Preset 导入、导出、保存和待重启状态。第一阶段页面提示明确说明当前生效配置不会因编辑或校验改变。
