# 知识库嵌入配置绑定与生命周期

## 使用方式

- 配置工作台展示当前知识库绑定的 embedding_* 非密钥参数。切换知识库需确认模型、方式及维度；未应用草稿可取消切换保留，确认切换则丢弃。
- 修改参数后统一点击“应用”：全局可热更新参数自动持久化，嵌入参数自动绑定当前库；已有索引、清空后保留的索引指纹或不兼容索引需要重建时先弹窗确认。空的新库直接绑定，无需清空重建。不需要重启服务，其他库嵌入配置不变。
- 新建库只在知识库管理页操作，默认使用创建时的全局嵌入配置，也可复制当前库已保存的绑定配置（包括密钥环境变量引用，不复制秘密值）。不复制文档、索引或未应用草稿；未绑定的库禁用复制选项。创建后可切换到新库，通过工作台“应用”调整模型。重建确认提示保留旧索引应选择新建库。
- 同时修改全局参数与嵌入参数时，先校验全部草稿并确认重建，再应用全局参数、绑定或重建当前库。两个持久化操作不是原子事务；若后者失败，明确提示全局部分已生效，保留未完成草稿供重试。不支持在线应用的重启参数会在写入前阻止整次应用。
- 弃用保留原始文件、Document、写入记录和索引；弃用库退出可选列表，禁止检索和写入。恢复后重新进入可选列表。默认库不能弃用或永久删除。
- 永久删除要求输入知识库完整名称：删除该库原始目录、写入记录、模型绑定及检索集合。目录和索引不可通过产品恢复；历史 Trace / 评估快照独立保留，Trace 读取时标识来源已删除。
- 本地 Qdrant 删除集合后可残留空的客户端存储目录；共享 Chroma 存储文件由后端管理，不删除整个存储目录，也不保证物理文件即时压缩。

## 持久化和安全边界

- catalog.sqlite3 添加生命周期状态和 embedding_bindings 表；旧表自动迁移，不删除旧数据。删除保留最小目录墓碑，用于 Trace 追溯。
- 模型配置只保存非秘密值和环境变量引用，默认引用 RAG_EMBEDDING_API_KEY。已有启动配置中的默认密钥可用于解析该引用；自定义引用通过进程环境解析。密钥本身不进入绑定记录、Trace 或评估快照。
- 每库独立 Embedder，索引写入和查询使用相同身份。auto 在绑定时冻结实际选择的模式。全局嵌入默认值只影响后续新库，不覆盖已有绑定。
- 旧库仅在当前模型指纹与已有索引模型指纹精确一致时自动绑定。无指纹或不一致时不猜测旧模型，展示待绑定并阻断不兼容索引。首次成功写入、显式重建会保存配置绑定。
- 绑定配置或密钥不可用时管理入口仍可访问，但不回退到其他嵌入模型。模型变更需要显式重建；失败保留恢复输入，索引标记失败并阻断后续检索。
- 弃用、绑定、删除在单进程内串行执行，并等待来源/索引操作完成。过期运行时拒绝后续检索和写入；删除中断保持弃用和不完整索引状态，可重试删除或恢复后重建。
- 删除前检查记录的索引存储身份；存储配置变更或 ES 管理客户端不可用时拒绝仅删除本地目录，以免遗留远程索引。
- 当前适用单服务进程。多 worker 协调、跨进程租约、鉴权与回收期尚未引入。
- 本轮绑定仅涵盖嵌入配置；生成、规划、重排及存储/分块仍使用全局设置，不随知识库切换。

## API

- POST /v1/knowledge-bases：可提供 embedding_binding 创建新库。
- POST /v1/knowledge-bases/{id}/embedding-binding：profile 与 rebuild；改变已有向量模型必须确认 rebuild=true。
- POST /v1/knowledge-bases/{id}/archive 或 restore。
- DELETE /v1/knowledge-bases/{id}：confirmation_name 必须准确匹配库名。
- 来源、Document、写入记录 GET 在弃用状态下只读可用；删除后返回 404。
- Trace GET /v1/traces/{id} 与列表附加 knowledge_base_status，这是读取时的当前状态，不改写原始快照。
