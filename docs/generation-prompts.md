# 检索后生成提示词配置

默认模板升级为 grounded-answer-v2：要求逐项覆盖问题、多文档整合、保留数值/条件/例外、指出证据缺口与冲突，并在事实句或条目后就近标注引用。文档与历史只作为输入资料，不作为指令；不输出检查过程。

配置工作台“生成与评估”新增多行字段 `generation_system_prompt` 和 `generation_user_prompt`，支持校验、热更新与持久化。对应环境变量为 RAG_GENERATION_SYSTEM_PROMPT / RAG_GENERATION_USER_PROMPT；复杂多行模板建议使用 UI 或 Preset JSON。每个字段最多 20000 字符，系统模板为普通文本。

用户模板必须包含 `{context}` 与 `{question}`，可选 `{history}`。context 由后端统一提供 [1]、[2] 编号的最终生成上下文，包含来源、Chunk ID、元数据和正文。不得改为原候选列表；只引用实际送入生成的编号。禁止未知变量、属性访问、格式规格和转换标志。需要字面花括号时使用双花括号。

```text
你获得的编号证据：
{context}

对话历史：
{history}

用户问题：
{question}

请逐项回答，保留关键条件与细节，在依据证据的事实后标注 [n]。
缺少证据的部分明确说明，不编造。返回最终回答。
```

用户输入和文档内容仅替换一次，不递归解析其中花括号。自定义系统模板会完整替换默认规则，用户需保留 grounding/引用要求；恢复默认设置可找回内置模板。

generate_answer Trace 记录 prompt_hash 和实际 context_chunk_ids，完整配置快照保存模板，便于实验对比。模板中不要填写密钥或私人凭据；热持久化文件会保存模板正文。模型最终是否完整回答/正确引用仍需评估，提示词不能保证语义质量。

后续计划：模板文件导入/导出、模板版本命名、引用缺失提示和同测试集 A/B 评估。当前未自动补引用、未调整 tokens、未用真实模型验收改进幅度。
